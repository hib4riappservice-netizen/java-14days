# 用語辞典 — 分からない言葉が出たら必ずここを引く

**使い方**：Ctrl+F（Macは⌘+F）で単語を検索してください。
**定義の中で使う言葉も、すべてこの辞典に載っています。** 定義を読んで分からない言葉があったら、それも引いてください（これを「芋づる引き」と呼びます。2〜3回引けば必ず底に着きます）。

## A. プログラミング全般

| 用語 | 読み | 意味（できるだけ日常語で） |
|---|---|---|
| ソースコード | — | 人間が読み書きする、プログラムの設計図となる文字列。ただの文章ファイル。「コード」「ソース」とも略す |
| コンパイル | — | 人間が書いたソースコードを、コンピュータが実行できる形に翻訳すること。Javaでは `.java` → `.class` に変換される |
| ビルド | — | コンパイルに加えて、必要な部品をかき集めて「実行できる1つの塊」にまとめる作業全体 |
| 実行（ラン） | — | できあがったプログラムを実際に動かすこと |
| 実装（インプリメント） | じっそう | 「コードを書くこと」の現場用語。「この機能を実装して」＝「この機能のコードを書いて」 |
| バグ | — | プログラムの間違い・不具合 |
| デバッグ | — | バグを見つけて直す作業 |
| デバッガ | — | プログラムを1行ずつ止めながら動かし、変数の中身を覗ける道具。IDEに付属 |
| IDE | アイディーイー | 統合開発環境。エディタ・コンパイラ・デバッガが全部入った開発用ソフト。例：IntelliJ IDEA |
| リファクタリング | — | 動きを変えずに、コードを読みやすく・直しやすく作り替えること |
| ライブラリ | — | 他人が作った便利な部品の詰め合わせ。自分で全部作らずに済む |
| フレームワーク | — | アプリの骨組みを最初から用意してくれる大型の仕組み。ライブラリは「呼ぶもの」、フレームワークは「呼ばれるもの」（後述の「制御の反転」参照）。例：Spring Boot |
| API | エーピーアイ | 「他のプログラムから使うための入口」の総称。①部品の使い方（メソッド一覧）②Web越しに呼べる機能、の両方の意味で使われる。文脈で判断する |
| 仕様 | しよう | 「何を作るか」を決めた取り決め。仕様書＝それを書いた文書 |
| 要件 | ようけん | 「システムが満たすべき条件」。仕様より前の段階の話 |
| ソースコード管理／バージョン管理 | — | コードの変更履歴を記録し、いつでも過去に戻せるようにする仕組み。例：Git |
| リポジトリ | — | バージョン管理下にあるプロジェクトの保管場所。「リポジトリ」＝プロジェクトのフォルダ全体＋履歴 |
| 環境 | かんきょう | プログラムが動く場所のこと。開発環境（自分のPC）／検証環境（テスト用サーバ）／本番環境（お客様が使う実物） |
| デプロイ | — | 作ったプログラムをサーバに配置して動かせる状態にすること |
| リリース | — | 利用者に使える状態で公開すること |
| ハードコーディング | — | 本来は設定ファイル等に外出しすべき値を、コードの中に直接書き込むこと。基本的に悪いこと |
| マジックナンバー | — | コード中に唐突に出てくる意味不明な数字（例：`if (status == 3)`）。定数にすべき |

## B. Java言語の基礎

| 用語                   | 意味                                                                                        |
| -------------------- | ----------------------------------------------------------------------------------------- |
| JDK                  | Java Development Kit。Javaを開発するための道具一式。これを入れないと始まらない                                       |
| JRE                  | Java Runtime Environment。Javaを「実行するだけ」の道具。JDKに含まれる                                        |
| JVM                  | Java Virtual Machine（Java仮想マシン）。コンパイル済みJavaプログラムを実際に動かすエンジン。これのおかげでWindowsでもMacでも同じコードが動く |
| LTS版                 | Long Term Support。長期間サポートされる安定版。実務では LTS を使う（Java 8, 11, 17, 21, 25 が該当）                  |
| クラス                  | Javaのすべてのコードを入れる箱。「設計図」に例えられる。ファイル名＝クラス名にする決まり                                            |
| オブジェクト／インスタンス        | クラス（設計図）から作られた実体。「たい焼きの型＝クラス、焼けたたい焼き＝オブジェクト」                                              |
| フィールド／メンバ変数          | クラスが持つデータ（属性）。例：`Employee` クラスの `name`, `age`                                             |
| メソッド                 | クラスが持つ処理のかたまり。他言語の「関数」に相当。「〜する」にあたる部分                                                     |
| 引数                   | ひきすう。メソッドに渡す入力値                                                                           |
| 戻り値／返り値              | メソッドが返す出力値                                                                                |
| 変数                   | 値を入れておく名前付きの箱                                                                             |
| 型（データ型）              | 変数に入れられる値の種類。Javaは「型を必ず宣言する言語」（静的型付け）である点が最大の特徴                                           |
| プリミティブ型              | 基本型。`int`（整数）`double`（小数）`boolean`（真偽）`char`（1文字）など8種類。中身が「値そのもの」                         |
| 参照型                  | プリミティブ型以外すべて。`String`, 配列, 自作クラスなど。中身は「値の置き場所を指す矢印」                                       |
| null                 | ヌル。「何も指していない」ことを表す特別な値。参照型のみが取りうる                                                         |
| NullPointerException | ヌルポ。null（何も無い）に対して操作しようとしたときに出るエラー。**新人が最も多く遭遇するエラー**                                     |
| 修飾子                  | クラスやメソッドの前につける性質を表す語。`public`, `private`, `static`, `final` など                            |
| public / private     | 公開範囲の指定。public＝どこからでも使える、private＝そのクラスの中だけ                                                |
| static               | スタティック。「インスタンスを作らなくても使える」という印。クラスに1個しか存在しない                                               |
| final                | ファイナル。「もう変更できない」という印。変数につけると定数になる                                                         |
| コンストラクタ              | オブジェクトが作られる瞬間に1回だけ動く、初期化専用のメソッド。クラス名と同じ名前                                                 |
| new                  | ニュー。オブジェクトを新しく作る命令。`new Employee()`                                                       |
| パッケージ                | クラスをまとめるフォルダのような仕組み。`com.example.attendance.service` のようにドット区切り                           |
| import               | インポート。他のパッケージのクラスを使うための宣言                                                                 |
| インタフェース              | 「こういうメソッドを持つこと」という約束だけを定めたもの。中身は書かない。**Javaで最重要の概念の1つ**                                   |
| 抽象クラス                | 一部だけ中身が書かれた、未完成のクラス。単体では実体化できない                                                           |
| 継承                   | けいしょう。既存クラスの性質を引き継いで新しいクラスを作ること。`extends`                                                 |
| オーバーライド              | 親クラスのメソッドを、子クラスで上書きすること                                                                   |
| オーバーロード              | 同じ名前で引数の違うメソッドを複数定義すること。オーバーライドと紛らわしいので注意                                                 |
| ポリモーフィズム／多態性         | ためたいせい。同じ呼び出し方で、相手によって違う動きをする性質。オブジェクト指向の核心                                               |
| カプセル化                | データを private で隠し、決められた入口（メソッド）経由でしか触らせないこと                                                |
| ゲッター／セッター            | フィールドを読む／書くための定型メソッド。`getName()` / `setName()`                                            |
| 例外                   | れいがい。プログラム実行中に起きた異常。Javaでは「例外オブジェクト」として投げられる                                              |
| 検査例外                 | チェック例外。コンパイラが「必ず対処せよ」と強制してくる例外。`IOException` など                                           |
| 非検査例外                | 実行時例外。対処を強制されない例外。`NullPointerException` など                                               |
| try-catch            | 例外が起きうる処理を囲み、起きたら捕まえて対処する構文                                                               |
| throw / throws       | throw＝例外を投げる。throws＝「このメソッドは例外を投げる可能性がある」という宣言                                            |
| スタックトレース             | 例外が起きたとき出る「どこで起きたか」の履歴。長いが読めば原因が分かる                                                       |
| コレクション               | 複数の値をまとめて扱う仕組みの総称。`List`, `Map`, `Set`                                                    |
| List                 | リスト。順番のある入れ物。同じ値を複数入れられる。実装：`ArrayList`                                                   |
| Map                  | マップ。キーと値のペアで管理する入れ物。辞書。実装：`HashMap`                                                       |
| Set                  | セット。重複を許さない入れ物                                                                            |
| ジェネリクス               | `List<String>` の `<String>` の部分。「中身の型」を指定して安全にする仕組み                                       |
| Optional             | 「値があるかもしれないし、無いかもしれない」を型で表す入れ物。NullPointerException対策                                     |
| ラムダ式                 | `x -> x * 2` のような、その場限りの短い処理の書き方                                                          |
| Stream API           | コレクションに対して「絞り込む→変換する→集める」を流れるように書ける仕組み                                                    |
| record               | レコード。「データを持つだけのクラス」を1行で書ける Java 16以降の記法                                                   |
| enum                 | イーナム／列挙型。取りうる値が決まっているものを型にする仕組み。例：曜日、ステータス                                                |
| var                  | 型を書かなくてもコンパイラに推測させる記法。Java 10以降。`var list = new ArrayList<String>();`                     |
| equals / hashCode    | 2つのオブジェクトが「同じ中身か」を判定するための仕組み。ペアで正しく実装する必要がある                                              |
| イミュータブル              | 不変。作った後、中身が変わらないオブジェクト。バグが減るので推奨される。`String` は不変                                          |
| ガベージコレクション           | GC。使われなくなったメモリをJVMが自動で片付ける仕組み                                                             |

## C. ツール・チーム開発

| 用語 | 意味 |
|---|---|
| Git | ギット。バージョン管理ツールの事実上の標準 |
| GitHub | ギットハブ。Gitのリポジトリをネット上に置いて共同作業するサービス |
| コミット | 変更を履歴として1つ記録すること。「セーブポイントを作る」イメージ |
| ブランチ | 枝。本流から分かれた作業線。他人に影響を与えずに作業できる |
| main / master | 本流のブランチ名。ここが「正」 |
| マージ | 枝で行った変更を本流に合流させること |
| コンフリクト | 衝突。同じ箇所を2人が別々に変更し、Gitが自動合流できない状態 |
| プルリクエスト（PR） | 「私の変更を本流に入れてください」という依頼。レビューはここで行う。GitLabでは「マージリクエスト」 |
| コードレビュー | 他人のコードを読んで指摘・承認する工程。品質の要 |
| リモート／ローカル | リモート＝GitHub側、ローカル＝自分のPC側 |
| クローン | リモートのリポジトリを自分のPCに丸ごとコピーすること |
| プッシュ／プル | プッシュ＝自分の変更をリモートに送る。プル＝リモートの変更を自分に取り込む |
| Maven / Gradle | メイヴン／グレイドル。ビルドツール。必要なライブラリの自動取得、コンパイル、テスト実行をまとめてやってくれる |
| pom.xml | Mavenの設定ファイル。使うライブラリをここに書く |
| 依存関係（デペンデンシー） | 自分のプログラムが必要としている外部ライブラリのこと |
| JUnit | ジェイユニット。Javaの単体テストを書くためのライブラリ。事実上の標準 |
| 単体テスト（ユニットテスト） | メソッド1個・クラス1個など、小さい単位が正しく動くか確かめるテスト |
| 結合テスト | 複数の部品を繋げた状態で正しく動くか確かめるテスト |
| モック | 本物の部品の代わりに置く「偽物」。テストを速く・安定させるために使う。ライブラリ：Mockito |
| アサーション | テストで「結果はこうなるはず」と表明する記述。`assertThat(actual).isEqualTo(expected)` |
| カバレッジ | テストがコードの何％を通ったかの指標 |
| CI | 継続的インテグレーション。コードを push するたび自動でビルド・テストを回す仕組み。例：GitHub Actions |
| チケット | 作業単位の管理票。「このチケットお願い」＝「この作業やって」。ツール：Jira, Backlog, Redmine |
| WBS | 作業を細かく分解した一覧表。進捗管理に使う |
| 見積り | その作業に何時間／何日かかるかの予測 |
| 手戻り | てもどり。一度終わった作業をやり直すこと。最も避けたいコスト |
| レガシーコード | 古くて手を入れにくい既存コード。テストが無いコードを指すことも多い |

## D. Web・データベース・アーキテクチャ

| 用語 | 意味 |
|---|---|
| サーバ／クライアント | サーバ＝サービスを提供する側のコンピュータ。クライアント＝それを使う側（ブラウザ、アプリ） |
| HTTP | ブラウザとサーバが会話するときの決まりごと（プロトコル）。HTTPSは暗号化版 |
| リクエスト／レスポンス | リクエスト＝クライアントからの要求。レスポンス＝サーバからの応答 |
| HTTPメソッド | 要求の種類。GET（取得）POST（新規作成）PUT（全体更新）PATCH（部分更新）DELETE（削除） |
| ステータスコード | 応答の結果を表す3桁の数字。200成功／201作成成功／400リクエストが変／401未認証／403権限なし／404見つからない／500サーバ側のエラー |
| URL / エンドポイント | エンドポイント＝APIの呼び出し先アドレス。例：`GET /api/employees/1` |
| パスパラメータ／クエリパラメータ | `/employees/1` の `1` がパスパラメータ。`/employees?dept=sales` の `dept=sales` がクエリパラメータ |
| リクエストボディ | POSTなどで送るデータ本体。通常JSON形式 |
| JSON | ジェイソン。データをやりとりする標準的な文字形式。`{"name":"田中","age":25}` |
| REST / RESTful | Web APIの設計スタイル。「URLでモノを表し、HTTPメソッドで操作を表す」という考え方 |
| ヘッダ | リクエスト／レスポンスに付ける付加情報。認証情報やデータ形式を入れる |
| 認証／認可 | 認証＝あなたは誰か確認。認可＝あなたに権限があるか確認。別物 |
| データベース（DB） | データを保存・検索する専用ソフト。例：PostgreSQL, MySQL, Oracle |
| RDB | リレーショナルデータベース。表（テーブル）形式でデータを持つDB。実務の主流 |
| テーブル／カラム／レコード | テーブル＝表。カラム＝列（項目）。レコード＝行（1件のデータ） |
| 主キー（PK） | その行を一意に特定できる列。例：社員ID |
| 外部キー（FK） | 他のテーブルの主キーを指す列。テーブル同士を繋ぐ |
| SQL | エスキューエル。DBに命令するための言語。SELECT（取得）INSERT（追加）UPDATE（更新）DELETE（削除） |
| JOIN | 複数テーブルを繋げて取得すること |
| インデックス | 検索を速くするための索引。付けすぎると書き込みが遅くなる |
| 正規化 | データの重複をなくすようテーブルを分割する設計手法 |
| トランザクション | 「まとめて成功、まとめて失敗」を保証する仕組み。振込の「引き落とし＋入金」が典型例 |
| コミット／ロールバック | トランザクションを確定する／なかったことにする |
| コネクションプール | DB接続を毎回作らず使い回す仕組み。性能のため必須 |
| ORM | オブジェクトとテーブルを自動対応させる仕組み。例：JPA / Hibernate |
| JPA / Hibernate | JavaのORM標準仕様（JPA）とその代表的実装（Hibernate） |
| Spring | Java業務システムで最も使われるフレームワーク |
| Spring Boot | Springを簡単に始められるようにしたもの。実務のデファクトスタンダード |
| DI（依存性の注入） | 必要な部品を自分で作らず、外から渡してもらう設計。テストしやすくなる。Springの中核 |
| IoC（制御の反転） | 「自分が呼ぶ」から「フレームワークに呼ばれる」への逆転。DIはその実現手段 |
| Bean | ビーン。Springが管理してくれるオブジェクトのこと |
| アノテーション | `@Override` `@Service` のような `@` で始まる目印。フレームワークへの指示に使う |
| レイヤードアーキテクチャ | 層構造の設計。Controller（受付）→ Service（業務ロジック）→ Repository（DB access）と役割を分ける |
| Controller | コントローラ。HTTPリクエストを受け取り、結果を返す層 |
| Service | サービス。業務ルール（ビジネスロジック）を書く層。**アプリの心臓部** |
| Repository / DAO | DBへの読み書きを担当する層 |
| Entity | エンティティ。DBのテーブル1行に対応するクラス |
| DTO | データ転送用オブジェクト。層をまたいでデータを運ぶための入れ物。EntityとDTOを分けるのが実務の定石 |
| ビジネスロジック | 「その業務ならではのルール」。例：「深夜22時以降は残業割増1.25倍」 |
| バリデーション | 入力値のチェック。「名前は必須」「年齢は0以上」など |
| ロギング | 動作記録を残すこと。障害調査の生命線。ライブラリ：SLF4J + Logback |
| 設定ファイル | 環境ごとに変わる値を外に出したファイル。Spring Bootでは `application.yml` |
| N+1問題 | 1回のクエリで済むはずが、ループ内でN回追加クエリが飛ぶ性能問題。**面接でも実務でも頻出** |
| SQLインジェクション | 入力値にSQLを混ぜ込まれて不正操作される攻撃。文字列連結でSQLを組むと発生 |

## E. 設計・品質

| 用語 | 意味 |
|---|---|
| 責務 | せきむ。「そのクラス／メソッドが担当する仕事」。1つに絞るのが良い設計 |
| 凝集度 | こうしゅうど。関係あるものがどれだけ1箇所にまとまっているか。高いほど良い |
| 結合度 | けつごうど。部品同士がどれだけ依存し合っているか。低いほど良い |
| SOLID原則 | 良い設計の5つの指針。単一責任／開放閉鎖／リスコフの置換／インタフェース分離／依存性逆転 |
| 単一責任の原則（SRP） | 1つのクラスは1つの理由でだけ変更されるべき |
| 開放閉鎖の原則（OCP） | 拡張には開き、修正には閉じる。＝新機能追加時に既存コードを触らずに済む形にする |
| 依存性逆転の原則（DIP） | 具体的なものではなく、抽象（インタフェース）に依存せよ |
| DRY | Don't Repeat Yourself。同じことを2箇所に書くな |
| YAGNI | You Aren't Gonna Need It。「将来使うかも」で作るな |
| KISS | Keep It Simple, Stupid. 単純に保て |
| デザインパターン | よくある設計問題への定石。例：Strategy, Factory, Singleton |
| 技術的負債 | 「とりあえず動く」で書いた雑なコードが将来生む利息（修正コスト） |
| 冪等性 | べきとうせい。何回実行しても結果が同じ性質。API設計で重要 |
| 名前付け | 変数・メソッド・クラスの命名。**コードの読みやすさの8割を決める、最重要スキル** |

## F. 追補（第2週で登場する語・レビュー第1回で追加）

| 用語 | 意味 |
|---|---|
| スコープ | 変数が「見える範囲」。`{ }` の中で宣言した変数は、その `{ }` の外からは見えない |
| 三項演算子 | `条件 ? 真のとき : 偽のとき` という短い書き方。`hours > 8 ? "残業" : "定時"` |
| キャメルケース | 2語目から大文字にする命名。`employeeName`。Javaの変数・メソッドの標準 |
| パスカルケース | 1語目から大文字。`EmployeeService`。Javaのクラス名の標準 |
| スネークケース | アンダースコアで繋ぐ命名。`employee_id`。DBのカラム名で使われる慣習 |
| 早期リターン | 条件に合わない場合を先に `return` で抜けて、ネストを浅くする書き方 |
| メソッド参照 | `Employee::getName` という書き方。`e -> e.getName()` の短縮形 |
| 遅延評価 | Streamで、最後に `toList()` 等を呼ぶまで実際の処理が走らない仕組み |
| スレッドセーフ | 複数の処理が同時に触っても壊れない性質。Webアプリは常に同時アクセスされるため重要 |
| プロキシ | 代理。Springは本物のクラスの「身代わり」を作り、その中で`@Transactional`等の処理を挟む。**同一クラス内呼び出しで`@Transactional`が効かない原因はこれ** |
| プレースホルダ | SQLの `?` や、ログの `{}` のような「後で値が入る穴」。SQLでは**SQLインジェクション対策の要** |
| 制約（DB） | DBが自動で守ってくれるルール。NOT NULL / UNIQUE / 外部キー など |
| H2 | インストール不要でJavaの中で動く軽量データベース。手軽だが**本番DBと挙動・方言が違う**ため、本教材では使わず PostgreSQL で統一する（Day 8 参照） |
| JPQL | JPA専用のクエリ言語。SQLに似ているが、テーブル名ではなく**Entityクラス名**を書く |
| 遅延読み込み（Lazy Loading） | 関連データを「実際に使うときまで取りに行かない」JPAの仕組み。N+1問題の主犯 |
| Lombok | ゲッターやコンストラクタを自動生成してくれるライブラリ。`@RequiredArgsConstructor` 等 |
| プロファイル | Spring Bootで環境（local/dev/prod）ごとに設定を切り替える仕組み |
| MDC | Mapped Diagnostic Context。ログに自動で付ける情報の置き場。トレースIDを入れるのに使う |
| トレースID | 1回のリクエストに割り振る識別子。ログを横断して1つの処理を追跡できる |
| テストピラミッド | 単体テストを最も多く、E2Eを最も少なくするテスト構成の指針 |
| FIRST原則 | 良いテストの5条件。Fast / Independent / Repeatable / Self-validating / Timely |
| BCrypt | パスワードを安全にハッシュ化するアルゴリズム。復号できないので流出しても悪用されにくい |
| ハッシュ化 | 元に戻せない形に変換すること。暗号化（戻せる）とは別物 |
| ボーイスカウトルール | 「来たときより美しくして帰る」。触ったコードの小さな汚れをついでに直す習慣 |
| ユビキタス言語 | 開発者と業務担当者が共通して使う用語集。認識ズレによる手戻りを防ぐ |
| 冪等性（べきとうせい） | 何度実行しても結果が同じ性質。GETやDELETEは冪等であるべき |
| 実行計画（EXPLAIN） | DBがそのSQLをどう処理するかの計画。遅いSQLの原因調査に使う |
| デファクトスタンダード | 公式規格ではないが、事実上の業界標準になっているもの |
| 正常系 / 異常系 | 正常系＝想定どおりの流れ。異常系＝エラーや不正入力の流れ |
| 境界値 | 条件の境目の値。「8時間以上」なら7.99 / 8.00 / 8.01。**バグの大半がここに潜む** |
| スコープ（案件） | その作業に含まれる範囲。「スコープ外」＝今回はやらないこと |

## G. 追補2（レビュー第3回で追加）

### 設計・開発の語
| 用語 | 意味 |
|---|---|
| 委譲（いじょう） | ある処理を、自分の中に持った別のオブジェクトに任せること。**継承の代わりに使うのが実務の定石**（継承より結合が緩い） |
| 密結合 / 疎結合 | 密結合＝部品同士が強く依存し、片方の変更が他方を壊す状態（悪い）。疎結合＝独立していて差し替えやすい状態（良い） |
| アンチパターン | 「よくやってしまうが、実は問題を起こす書き方・設計」のこと |
| テンプレートメソッド | 全体の処理の流れを親クラスが決め、変わる部分だけ子クラスに書かせるデザインパターン |
| Strategy（ストラテジ） | 処理のやり方をインタフェースで差し替え可能にするデザインパターン。Day 4 でやった `WorkTimeRule` がこれ |
| Factory（ファクトリ） | オブジェクトの生成処理を専用のクラスにまとめるパターン |
| Singleton（シングルトン） | インスタンスを1つだけに制限するパターン。Spring の Bean は既定でこれ |
| Adapter（アダプタ） | 形の合わない既存部品を、自分の使いたい形に変換して繋ぐパターン |
| スタブ | テスト用に「決まった値を返すだけ」の偽物部品。モックとほぼ同義で使われることが多い |
| デグレ / リグレッション | 今まで動いていた機能が、修正によって壊れること。**自動テストはこれを防ぐためにある** |
| OSS | オープンソースソフトウェア。ソースが公開され自由に使えるもの。Spring も JUnit も OSS |
| javadoc | Javaのソースコード内コメント（`/** ... */`）から自動生成される仕様書 |
| 可観測性 | システムの中で何が起きているかを外から把握できる度合い。ログ・メトリクス・トレースの3本柱 |
| グレースフルシャットダウン | 処理中のリクエストを最後まで終わらせてから、安全にアプリを停止すること |
| ヘルスチェック | アプリが正常に動いているかを外部から確認する仕組み。`/actuator/health` など |
| 冗長化 | 同じものを複数用意し、1つ壊れても止まらないようにすること |
| プロファイリング | 実行中のアプリを計測し、どこが遅い／メモリを食っているかを特定する作業 |
| デッドロック | 2つの処理が互いの解放待ちになり、どちらも進めなくなる状態 |
| トランザクション分離レベル | 同時実行中のトランザクションが、互いをどこまで見えるかの設定。READ COMMITTED など |
| Testcontainers | テスト実行時に本物のDBをDockerで自動起動してくれるライブラリ。**「本番と同じDBでテストする」を実現する** |
| E2Eテスト | End to End。ブラウザ操作から DB まで、利用者と同じ経路で通しで確認するテスト |
| OWASP | Webアプリのセキュリティに関する国際的な非営利団体。「OWASP Top 10」は代表的な脆弱性の一覧 |
| XSS | クロスサイトスクリプティング。悪意のあるスクリプトを画面に埋め込まれる攻撃 |
| CSRF | 利用者になりすまして意図しない操作を実行させる攻撃 |

### チーム運営の語
| 用語 | 意味 |
|---|---|
| スプリント | アジャイル開発における、1〜2週間の作業サイクルの単位 |
| 起票（きひょう） | チケットを新規作成すること。「別チケットで起票します」＝「別作業として登録します」 |
| 受け入れ条件 | そのチケットが「完了した」と認められる条件。着手前に確認するのが鉄則 |
| Definition of Done（完了の定義） | チーム共通の「これが全部満たされたら完了」という基準。実装だけでなくテスト・レビュー・ドキュメントを含む |

### 勤怠・労務の業務用語（総合課題で使用）
| 用語 | 意味 |
|---|---|
| 打刻（だこく） | 出勤・退勤の時刻を記録すること |
| 打刻漏れ | 出勤または退勤の打刻を忘れること。**実務で頻繁に起きるため、必ず設計で考慮が必要** |
| 所定労働時間 | 会社が就業規則で定めた1日の標準勤務時間。本教材では8時間 |
| 法定労働時間 | 労働基準法32条が定める上限。1日8時間・週40時間 |
| 割増賃金 | 時間外・深夜・休日労働に対して上乗せされる賃金。法定は時間外25%以上 |
| 36協定（さぶろくきょうてい） | 残業をさせるために必要な労使協定。労働基準法36条に由来。原則上限は月45時間・年360時間 |
| 締め（しめ） | 月末に勤怠を確定させ、以降変更できなくすること。給与計算の前提となる |

> **業務用語を最初に定義するのは、実務の作法です。** 開発者と業務担当者が同じ言葉を違う意味で使っていると、必ず手戻りが起きます。この用語集のことを**ユビキタス言語**と呼びます。

## H. 追補3（実務標準の開発環境まわり）

| 用語 | 意味 |
|---|---|
| コンテナ | アプリと必要なもの一式を1つの箱に詰めて動かす仕組み。**「私のPCでは動く」問題を消す**ための技術 |
| Docker | コンテナを扱う代表的なツール。DBやミドルウェアを「インストールせずに起動する」ために現場で日常的に使う |
| イメージ | コンテナの元になるひな型。`postgres:16` のように**名前とバージョンで固定する**（`latest` は使わない） |
| Docker Compose | 複数のコンテナ（DB・アプリ等）の起動をまとめて定義するファイル（`compose.yaml`）とコマンド。ローカル開発環境の共有に必須 |
| ボリューム | コンテナを消してもデータを残すための保存領域。DBのデータはここに置く |
| マイグレーション | データベースのテーブル定義の変更を、**連番付きのSQLファイルとして履歴管理**すること。手作業のDDLを禁止するための仕組み |
| Flyway | Java界の代表的なマイグレーションツール。`V1__xxx.sql` を起動時に未適用のぶんだけ自動実行する。競合製品に Liquibase |
| `flyway_schema_history` | Flyway が「どのファイルをいつ適用したか」を記録するテーブル。**手で編集しない** |
| `@ServiceConnection` | Testcontainers が起動したDBの接続情報を、Spring Boot に自動連携させるアノテーション（Spring Boot 3.1以降） |
| ブランチ保護 / Ruleset | `main` への直接 push を禁止し、PRとCI通過を必須にする GitHub の設定。**現場では原則必ず設定されている** |
| アノテーションプロセッサ | コンパイル時にコードを自動生成する仕組み。Lombok はこれで動くため、IDE側で有効化が必要 |
| switch 式 | `case A -> 値;` の形で**値を返せる** switch（Java 14以降）。`break` 不要で、書き漏らしをコンパイラが検出できる |
| テキストブロック | `"""` で囲む複数行の文字列（Java 15以降）。JSONやSQLをエスケープなしで書ける |
| 型推論 | 右辺から変数の型をコンパイラが判断する仕組み。`var` がこれにあたる。**型が消えるわけではない** |
