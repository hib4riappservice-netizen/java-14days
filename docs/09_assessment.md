## 第2部：コードを読む（20点）
以下のコードには**バグが4つ**あります。すべて指摘し、修正してください。（各5点）

```java
public class SalaryCalculator {
    public String judge(List<String> departments, String target, double base, int count) {
        for (String d : departments) {
            if (d == target) {
                return "found";
            }
        }
        double average = base / count;
        String result = null;
        if (average > 300000) {
            result = "high";
        }
        return result.toUpperCase();
    }
}
```

<details>
<summary>解答（自分で4つ挙げてから開く）</summary>

1. **`d == target`** — 文字列の比較に `==` を使っている。内容が同じでも別インスタンスなら false になる → `d.equals(target)` または `Objects.equals(d, target)` にする
2. **`base / count`** — `count` が 0 のとき。`double` の除算なので例外にはならないが `Infinity` になり、以降の判定が壊れる → `count <= 0` のチェックが必要
3. **`result.toUpperCase()`** — `average <= 300000` のとき `result` が null のままで NullPointerException → 初期値を設定するか、else 節を書く
4. **`departments` が null のとき** — 拡張for文で NullPointerException → null チェックまたは `Objects.requireNonNull`
5. （加点）金額に `double` を使っている → `BigDecimal` にすべき
6. （加点）メソッド名 `judge` と戻り値 `"found"` の意味が不明。責務が2つ混在している

**4つ以上指摘できたら満点。5・6も挙げられたら、既に良い目です。**
</details>

## 第2部：設計レビューをする（25点）
以下のコードをレビューし、**指摘を5つ以上**、重要度（`[must]` / `[want]` / `[nits]`）付きで書いてください。

```java
@RestController
public class AttendanceController {

    @Autowired
    private AttendanceRepository repository;

    @PostMapping("/api/attendances")
    public AttendanceEntity register(@RequestBody AttendanceEntity entity) {
        if (entity.getClockOut().isBefore(entity.getClockIn())) {
            return null;
        }
        entity.setCreatedAt(LocalDateTime.now());
        return repository.save(entity);
    }

    @GetMapping("/api/attendances/{id}")
    public AttendanceEntity find(@PathVariable Long id) {
        try {
            return repository.findById(id).get();
        } catch (Exception e) {
            return null;
        }
    }
}
```

<details>
<summary>解答（自分で5つ挙げてから開く）</summary>

```
[must] Controller が Repository を直接呼んでおり、Service 層を飛ばしています。
       業務ロジック（時刻の前後判定）が Controller に書かれている点も同様の問題です。
       AttendanceService を作り、そこに移してください。

[must] Entity を @RequestBody と戻り値の両方に使っています。
       DBの内部構造がAPI仕様に直結し、また不要な項目（createdAt等）が外部に露出します。
       Request/Response 用の DTO を分離してください。

[must] 検証エラー時に null を返しています。HTTPステータスは200のまま、
       ボディが null になるため、クライアントは成功と失敗を区別できません。
       400 Bad Request を返してください。

[must] find() で catch (Exception e) して null を返しています。
       例外の握りつぶしです。障害が起きても検知できません。
       存在しない場合は 404 を返してください。

[must] repository.findById(id).get() を isPresent チェックなしで呼んでいます。
       存在しない ID で NoSuchElementException が発生します。
       orElseThrow(() -> new AttendanceNotFoundException(id)) にしてください。

[must] entity.getClockOut() の null チェックがありません。
       退勤打刻が無いリクエストで NullPointerException になります。

[want] @Autowired フィールドインジェクションを使っています。
       final にできずテストしにくいため、コンストラクタインジェクションを推奨します。

[want] @RequestBody にバリデーション（@Valid）がありません。
       必須項目チェックが一切効いていません。

[want] LocalDateTime.now() を直接呼んでいるため、時刻を固定したテストが書けません。
       Clock を注入する形を推奨します。

[want] @RequestMapping("/api/attendances") をクラスに付けると、
       各メソッドのパス指定が簡潔になります。

[want] トランザクション境界がありません。今は単一保存なので問題は顕在化しませんが、
       処理が増えたとき整合性が壊れます。Service に @Transactional を付けてください。

[nits] 登録成功時は 201 Created を返すのが REST の慣習です。
```

**採点**：`[must]` を4つ以上指摘 → 20点 / 3つ → 15点 / 2つ → 10点 / 1つ以下 → 5点
`[want]` を2つ以上追加で +5点

**`[must]` を4つ以上見つけられたなら、あなたは既にレビューができる新人です。**
</details>
